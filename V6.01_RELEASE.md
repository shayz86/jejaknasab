# JejakNasab V6.01 — Public Link & D1 Compatibility Fix

V6.01 is a maintenance release focused on the public `/f/[token]` link and compatibility with existing Cloudflare D1 databases.

## Fixes

- Makes V6 schema initialization idempotent and independent per DDL statement.
- Checks columns with `PRAGMA table_info` before running `ALTER TABLE`.
- Prevents an already-existing V6 column from blocking unrelated schema setup.
- Keeps the V5 optional-lineage → V6 Cabang Keluarga conversion idempotent.
- Adds `GET /api/health` for deployment/D1 diagnostics.
- Public-link API errors now expose the HTTP status to the frontend.
- Public link error screen now provides a reload action and basic deployment/link guidance.
- Existing family data is not deleted, reset, or recreated.

## Important deployment note

Cloudflare Pages Functions require the `/functions` directory to be deployed with the Pages project. The D1 database must also be bound as `DB` in the production Pages environment.

For an existing database, V6.01 can be deployed without resetting D1. If you use the migration file manually, run `migration-v6.sql` once against the production database.

## Diagnostic endpoint

After deployment, open:

`https://YOUR-DOMAIN/api/health`

A healthy response contains `ok: true`, the V6.01 version, and counts for trees, persons, and public trees.
