# Deploy JejakNasab V6.01

## 1. Push source

```bash
git add .
git commit -m "fix: public link and D1 compatibility v6.01"
git push origin main
```

## 2. Cloudflare Pages

Confirm the Pages project is connected to the same GitHub repository and that the latest deployment is **Production**.

The project must deploy the root `functions/` directory because Pages Functions use file-based routing.

## 3. D1 binding

Cloudflare Pages → project → Settings → Bindings → D1 database:

- Variable name: `DB`
- Database: `jejaknasab-db`

Redeploy after changing a binding.

## 4. Secrets / variables

Keep the existing production values for:

- `SESSION_SECRET`
- `OWNER_SETUP_KEY`
- optional `PREMIUM_PRICE`
- optional `ULTIMATE_PRICE`
- optional `PAYMENT_INSTRUCTIONS`

## 5. Check API

Open:

`https://jejaknasab.pages.dev/api/health`

Expected shape:

```json
{"ok":true,"version":"6.01","db":true,"trees":...,"persons":...,"publicTrees":...}
```

If this is healthy, test the existing public URL:

`https://jejaknasab.pages.dev/f/<TOKEN>`

## 6. D1 migration

V6.01 no longer requires repeating `ALTER TABLE` statements that can fail when the columns already exist. The application performs safe, idempotent column checks at runtime.

If the V6 branch tables have never been created, you may run:

```bash
npx wrangler d1 execute jejaknasab-db --remote --file=migration-v6.sql
```

Do **not** reset, drop, or recreate the production database.
